The Yabetoo API uses conventional HTTP response codes to indicate the success or failure of an API request.

## HTTP Status Codes

| Code | Status | Description |
|------|--------|-------------|
| `200` | OK | Request succeeded |
| `201` | Created | Resource created successfully |
| `400` | Bad Request | Invalid request parameters |
| `401` | Unauthorized | Invalid or missing API key |
| `403` | Forbidden | Insufficient permissions |
| `404` | Not Found | Resource does not exist |
| `429` | Too Many Requests | Rate limit exceeded |
| `500` | Internal Server Error | Server-side error |

## Payment Error Codes

When a payment fails, the API returns specific error codes to help you understand what went wrong:

| Code | Description |
|------|-------------|
| `LOW_BALANCE_OR_PAYEE_LIMIT_REACHED_OR_NOT_ALLOWED` | The customer has insufficient funds, has reached their transaction limit, or the transaction is not allowed by the operator |
| `TIMEOUT` | The customer did not confirm the payment in time (did not enter their PIN) |

### Example Error Response

```json
{
  "error": {
    "message": "LOW_BALANCE_OR_PAYEE_LIMIT_REACHED_OR_NOT_ALLOWED",
    "code": "LOW_BALANCE_OR_PAYEE_LIMIT_REACHED_OR_NOT_ALLOWED"
  }
}
```

## IP Address Not Allowed

A live secret key restricted to an [IP allowlist](/en/payments/api-keys#restrict-a-key-to-ip-addresses) refuses any call coming from another address:

```json
{
  "status": 403,
  "path": "/v1/disbursements",
  "timestamp": "2025-03-17T10:24:57.559+01:00",
  "code": "E_IP_NOT_ALLOWED",
  "message": "Forbidden",
  "detail": "This API key cannot be used from this IP address."
}
```

The response gives neither the key's list nor the address seen. Call from an allowed address, or add yours in the dashboard (the change applies within 5 minutes).

## Disbursement Refused

`POST /v1/disbursements` can answer `403` with `code: "E_RISK_BLOCKED"` and `failure_code: "risk_blocked"`: the disbursement is refused before anything is written (nothing is created, no funds are reserved). Do not replay the request; contact support. See [Create a disbursement](/en/api-reference/disbursement/create#403-disbursement-refused).

## Disbursement Failure Codes

A `failed` disbursement carries a `failureCode`. Three of them come from disbursement verification. The field is named `failure_code` in the 403 error and `failureCode` on the disbursement object.

| `failureCode` | Description |
|----------------|-------------|
| `risk_blocked` | Disbursement refused by verification. At creation, `403 E_RISK_BLOCKED` response: no disbursement exists. On a disbursement already held for review and then refused after the fact: `failed`, `review.status: "rejected"`, funds returned |
| `risk_review_rejected` | Verification refused the disbursement held for review; the funds are released |
| `risk_review_expired` | No decision within 48 h: the disbursement is canceled and the funds are released |

## Best Practices

1. **Always handle errors gracefully** - Never expose raw error messages to end users
2. **Log errors for debugging** - Store error details for troubleshooting
3. **Implement retry logic** - For rate limits and temporary failures
4. **Validate before sending** - Check parameters client-side to reduce errors

<Note>
  If you encounter persistent errors, contact support@yabetoopay.com with the error details.
</Note>
