A **connected account** represents a seller. Creating it gives them their identity, their
organization and their wallet at Yabetoo — but **not yet** the right to receive money: they
must first pass verification.

```bash
POST https://pay.sandbox.yabetoopay.com/v1/connect/accounts   # Sandbox
POST https://pay.api.yabetoopay.com/v1/connect/accounts       # Production
```

## Headers

| Header | Required | Rule |
|---|---|---|
| `Authorization: Bearer sk_…` | Yes | Your marketplace secret key |
| `Idempotency-Key` | **Yes** | Non-empty string, 255 characters maximum |

<Warning>
**`Idempotency-Key` is required on this route**, unlike most Yabetoo endpoints. Creating a
seller is **irreversible**: without a key, a single network retry would create two permanent
sellers, and no endpoint lets you unlink or merge them.
</Warning>

## Request body

| Parameter | Type | Required | Description |
|---|---|---|---|
| `country` | `string` | Yes | ISO 3166-1 alpha-2 country code, e.g. `CG` |
| `currency` | `string` | Yes | ISO 4217 currency code, e.g. `XAF` |
| `name` | `string` | Yes | Legal or trading name of the seller, 255 characters max |
| `email` | `string` | Yes | The seller's email address, 255 characters max |

<Warning>
**`email` is required and must be the seller's, not yours.** It is the only channel through
which Yabetoo reaches the seller — in particular for the confirmation code of their payouts.
</Warning>

<Note>
**The country is a business decision, not a copy of your own.** It determines the compliance
requirements of your seller's KYC file. A Congolese marketplace can connect a seller from
another supported country.
</Note>

### Rejected fields

Three fields are **explicitly rejected with a 422** — they are never silently ignored:

| Field | Why |
|---|---|
| `phone` | The seller registers their own payout number during their KYC onboarding. Accepting it here would let you believe you had registered a destination that does not exist. |
| `type` | A connected seller is always `business`. The type decides nothing: their file is opened with the `connected_account` requirements. |
| `fee_payer` | Who pays Yabetoo's fees is **derived** from your `connect_mode`, set once at [activation](/en/connect/activate). |

If you send several of them, they are **all named in the same response** — you do not have to
fix one field at a time.

## Example

<CodeGroup>
```bash cURL
curl -X POST https://pay.sandbox.yabetoopay.com/v1/connect/accounts \
  -H "Authorization: Bearer YOUR_SECRET_KEY" \
  -H "Idempotency-Key: vendor-ada-2026-09-04" \
  -H "Content-Type: application/json" \
  -d '{
    "country": "CG",
    "currency": "XAF",
    "name": "Boutique Ada",
    "email": "ada@example.com"
  }'
```

```javascript fetch
const res = await fetch(
  "https://pay.sandbox.yabetoopay.com/v1/connect/accounts",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.YABETOO_API_KEY}`,
      "Idempotency-Key": `vendor-${localVendorId}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      country: "CG",
      currency: "XAF",
      name: "Boutique Ada",
      email: "ada@example.com",
    }),
  }
);

const account = await res.json();
```

```python Python
import os, requests

res = requests.post(
    "https://pay.sandbox.yabetoopay.com/v1/connect/accounts",
    headers={
        "Authorization": f"Bearer {os.environ['YABETOO_API_KEY']}",
        "Idempotency-Key": f"vendor-{local_vendor_id}",
    },
    json={
        "country": "CG",
        "currency": "XAF",
        "name": "Boutique Ada",
        "email": "ada@example.com",
    },
)
account = res.json()
```
</CodeGroup>

## Response

```json 201
{
  "id": "acct_01HZVENDOR0000000000000000",
  "object": "connect_account",
  "controller_account_id": "acct_01HZMARKETPLACE00000000000",
  "organization_id": "org_01HZ000000000000000000000",
  "type": "business",
  "name": "Boutique Ada",
  "email": "ada@example.com",
  "status": "active",
  "environment": "test",
  "fee_payer": "controller",
  "created_at": "2026-09-04T10:00:00.000Z"
}
```

<Warning>
**`status: "active"` does not mean "ready to collect".** At this point the seller has
**no KYC file, no payout destination and no wallet**. Nothing can leave their account until
they have completed their
[onboarding](/en/connect/accounts/onboarding). This field only says that the account exists.
</Warning>

<Note>
The seller's `environment` is **inherited from the key you used**: an `sk_test_` can only
produce a test seller. It is then impossible to target a `live` seller with a test key — the
response is a `401`.
</Note>

## Replays

Reusing the same `Idempotency-Key` returns **the same `201` with the same `id`**, within 24 h
(response cache) and beyond it (uniqueness in the database). You will never create two sellers
by accident.

A key that is **already being processed** returns `409 E_IDEMPOTENCY_CONFLICT`: retry once the
first call has finished.

## Errors

| Status | Code | Cause |
|---|---|---|
| `422` | `errors[].rule = "unsupported"` | `phone`, `type` or `fee_payer` sent |
| `422` | `errors[].field = "Idempotency-Key"` | Header missing or too long |
| `422` | `connect.controller_mode_unset` | **Connect is not activated on your account** — see [Activate Connect](/en/connect/activate) |
| `422` | validation | `country`, `currency`, `name` or `email` invalid, or unknown country/currency code |
| `409` | `E_IDEMPOTENCY_CONFLICT` | A request with the same key is in flight |
| `429` | `E_TOO_MANY_REQUESTS` | More than **20 creations per minute** |
| `503` | `E_SSO_UNAVAILABLE` | The identity service is unavailable |

## Model constraints

<AccordionGroup>
  <Accordion title="A seller belongs to a single marketplace, forever">
    The control link is set here and it is immutable. There is neither unlinking, nor
    transfer to another marketplace.
  </Accordion>
  <Accordion title="A seller cannot connect other sellers">
    Depth is limited to 1.
  </Accordion>
  <Accordion title="The currency must be that of your account">
    Multi-currency is not supported: an allocation or a split between two different
    currencies is rejected with `422 E_CURRENCY_MISMATCH`.
  </Accordion>
</AccordionGroup>
