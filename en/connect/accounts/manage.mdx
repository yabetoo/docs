Three read operations, all bounded to **your** sellers: your marketplace identifier comes from
your API key and cannot be supplied in the request.

## List your sellers

```bash
GET /v1/connect/accounts
```

| Parameter | Type | Description |
|---|---|---|
| `limit` | `number` | 1 to 100. Above that, the value is brought back down to 100. |
| `cursor` | `string` | Opaque cursor returned by the previous page |

<CodeGroup>
```bash cURL
curl "https://pay.sandbox.yabetoopay.com/v1/connect/accounts?limit=20" \
  -H "Authorization: Bearer YOUR_SECRET_KEY"
```
</CodeGroup>

```json 200
{
  "object": "list",
  "data": [
    {
      "id": "acct_01HZVENDOR0000000000000000",
      "object": "connect_account",
      "controller_account_id": "acct_01HZMARKETPLACE00000000000",
      "organization_id": "org_01HZ000000000000000000000",
      "type": "business",
      "name": "Boutique Ada",
      "email": "ada@example.com",
      "status": "active",
      "environment": "test",
      "fee_payer": "controller",
      "country": "CG",
      "currency": "xaf",
      "created_at": "2026-09-01T09:12:00.000Z"
    }
  ],
  "has_more": false,
  "next_cursor": null

```

<Note>
The list does **not** carry balances: that would be one query per seller. Read a seller's
detail for their balances.
</Note>

## Read a seller

```bash
GET /v1/connect/accounts/{acct}
```

```json 200
{
  "id": "acct_01HZVENDOR0000000000000000",
  "object": "connect_account",
  "controller_account_id": "acct_01HZMARKETPLACE00000000000",
  "name": "Boutique Ada",
  "email": "ada@example.com",
  "organization_id": "org_01HZ000000000000000000000",
  "country": "CG",
  "status": "active",
  "environment": "test",
  "fee_payer": "controller",
  "balances": [
    {
      "currency": "xaf",
      "balance": 4000,
      "pending_balance": 8975,
      "held_balance": 0,
      "next_maturity_at": "2026-09-11T00:00:00.000Z"
    }
  ]
}
```

<ResponseField name="balances" type="array">
  One entry **per currency**. A seller created but never paid returns `[]` — this is a
  nominal state, and the response stays `200`.
</ResponseField>

<ResponseField name="balance" type="number">
  The **available** balance: this is the only withdrawable amount.
</ResponseField>

<ResponseField name="pending_balance" type="number">
  Funds credited but **not yet matured**. They are not withdrawable, but they remain
  seizable by a refund.
</ResponseField>

<ResponseField name="held_balance" type="number">
  Funds **committed to a payout in flight**. Do not confuse them with `pending_balance`:
  these are two different states.
</ResponseField>

<ResponseField name="next_maturity_at" type="string | null">
  The date on which the next pending credit will become available. `null` if there is
  nothing pending.
</ResponseField>

## Read a seller's history

```bash
GET /v1/connect/accounts/{acct}/transactions
```

| Parameter | Type | Description |
|---|---|---|
| `page` | `number` | Starting at 1 |
| `limit` | `number` | 25 by default, 100 at most |

```json 200
{
  "object": "list",
  "data": [
    {
      "id": "wtx_01HZ00000000000000000000",
      "object": "connect_allocation",
      "amount": 8910,
      "currency": "xaf",
      "amount_fee": 90,
      "created_at": "2026-09-01T09:20:00.000Z",
      "available_at": "2026-09-08T09:20:00.000Z",
      "matured_at": null
    }
  ],
  "has_more": true
}
```

<Note>
This list is paginated **by page number**, not by cursor — so it does not return a
`next_cursor`.
</Note>

The two dates are read together:

| `available_at` | `matured_at` | Meaning |
|---|---|---|
| a date | `null` | **Pending** credit — it will become available on that date |
| a date | a date | **Matured** credit, available |
| `null` | `null` | Credit **immediately available**, with no delay |

## Errors common to all three reads

| Status | Cause |
|---|---|
| `401` | Key missing, or test key targeting a `live` seller |
| `403` | Unknown seller, malformed identifier, or seller of another marketplace |
| `503` | The identity service is unavailable |
