## What is a Product?

A **Product** represents an item or service you sell. It's the base entity of your catalog, around which prices and promotions revolve.

A price is attached to the product through `productId`. A SaaS plan or a service offering is therefore a product with one or more prices.

<Info>
  **Identifier format**: `prod_` followed by 36 alphanumeric characters.

  Example: `prod_abc123def456ghi789jkl012mno345`
</Info>

## Product Attributes

### Main Attributes

| Attribute | Type | Description |
|-----------|------|-------------|
| `id` | string | Unique product identifier |
| `name` | string | Product name shown to customers |
| `description` | string | Detailed product description |
| `type` | enum | Product type: `physical`, `digital`, `service` |
| `status` | enum | Status: `active`, `archived`, `draft` |
| `price` | number \| null | Default price (optional) |
| `category` | number | Product category |
| `subscriptionEligible` | boolean | Can be sold as a subscription |
| `prices` | array | The **active** prices attached to the product |

## Product Types

<Tabs>
  <Tab title="Physical">
    ### Physical Product (`physical`)

    A tangible product that requires shipping to the customer.

    **Characteristics:**
    - Stock management enabled
    - Shipping address required
    - Shipment tracking available

    **Examples:** Clothing, electronics, printed books, accessories

    ```json
    {
      "name": "Premium T-shirt",
      "type": "physical",
      "description": "100% organic cotton t-shirt"
    }
    ```
  </Tab>

  <Tab title="Digital">
    ### Digital Product (`digital`)

    A dematerialized product accessible by download.

    **Characteristics:**
    - Instant delivery after payment
    - Secure download links
    - Download count control
    - Optional link expiration

    **Examples:** E-books, software, video courses, templates

    ```json
    {
      "name": "Advanced React Course",
      "type": "digital",
      "description": "20 hours of video + resources",
      "subscriptionEligible": false
    }
    ```
  </Tab>

  <Tab title="Service">
    ### Service (`service`)

    A one-off or ongoing service offering.

    **Characteristics:**
    - No physical stock
    - Ideal for subscriptions
    - Recurring billing available

    **Examples:** Consulting, SaaS subscriptions, maintenance, coaching

    ```json
    {
      "name": "Pro Subscription",
      "type": "service",
      "description": "Unlimited access to all features",
      "subscriptionEligible": true
    }
    ```
  </Tab>
</Tabs>

## Product Statuses

The status determines the product's visibility and availability:

<CardGroup cols={3}>
  <Card title="Active" icon="circle-check" color="#22c55e">
    The product is visible and available for purchase. Customers can buy it.
  </Card>
  <Card title="Draft" icon="pencil" color="#f59e0b">
    A draft being created. Not visible to customers.
  </Card>
  <Card title="Archived" icon="box-archive" color="#6b7280">
    An archived product. Not visible but kept for history.
  </Card>
</CardGroup>

```typescript
enum ProductStatus {
  ACTIVE = 'active',      // Available for purchase
  DRAFT = 'draft',        // Being created
  ARCHIVED = 'archived'   // Archived
}
```

## Create a Product

Products are created on `POST /v1/products`, with their default price posed in the **same
call**.

### Request Body

<ParamField body="name" type="string" required>
  Product name, 3 to 70 characters.
</ParamField>

<ParamField body="description" type="string" required>
  Product description, 10 to 255 characters.
</ParamField>

<ParamField body="type" type="enum" required>
  `physical`, `digital`, or `service`.
</ParamField>

<ParamField body="category" type="number" required>
  Product category, strictly positive.
</ParamField>

<ParamField body="subscriptionEligible" type="boolean" required>
  Whether the product can be sold as a subscription.
</ParamField>

<ParamField body="status" type="enum" default="draft">
  `active`, `draft`, or `archived`.
</ParamField>

<ParamField body="defaultPriceData" type="object">
  The product's price, posed in the same call. **Optional**: a product can be created without
  a price, then get one later through `POST /v1/prices`. Field details below.
</ParamField>

<Note>
  `accountId` is **not** a request body field: the account that owns the product is derived
  from the API key used for the call, not from a value the caller sends.
</Note>

<Steps>
  <Step title="Create the product with its price">
    ```bash
    curl -X POST https://api.yabetoo.com/v1/products \
      -H "Authorization: Bearer sk_live_..." \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Pro Plan",
        "description": "Monthly subscription",
        "type": "service",
        "category": 3,
        "subscriptionEligible": true,
        "defaultPriceData": {
          "amount": 25000,
          "currency": "xaf",
          "type": "recurring",
          "billingInterval": "month",
          "billingIntervalCount": 1
        }
      }'
    ```
  </Step>

  <Step title="Add a second price (optional)">
    An annual tier next to the monthly one, or a second currency: `POST /v1/prices` with
    `productId`.

    See [Price Documentation](/en/products/prices)
  </Step>
</Steps>

### `defaultPriceData`

<ParamField body="amount" type="number" required>
  Amount in the currency's main unit. Strictly positive, up to `99999999.99`.
</ParamField>

<ParamField body="currency" type="string" required>
  Currency code, exactly 3 characters. **Required** — there is no default currency.
</ParamField>

<ParamField body="type" type="enum" required>
  `one_time` or `recurring`.
</ParamField>

<ParamField body="billingInterval" type="enum">
  `day`, `week`, `month`, or `year`. Recurring prices only.
</ParamField>

<ParamField body="billingIntervalCount" type="number">
  Number of intervals per billing cycle. Strictly positive.
</ParamField>

<ParamField body="trialPeriodDays" type="number">
  Free trial days, `0` or more.
</ParamField>

<Warning>
  **`defaultPriceData` cannot be combined with the legacy batch pricing configuration of the
  request body.** Sending both in the same call is refused with **422**
  (`E_CONFLICTING_PRICE_INPUT`): each would create an active price, and the two would coexist
  on the product with no way to tell which one applies. Send `defaultPriceData` alone — this
  is the recommended path.
</Warning>

## API Response

`GET /v1/products` and `GET /v1/products/{id}` return the product with its prices.

<ResponseField name="prices" type="array">
  The prices attached to the product. **Active prices only** — deactivated prices are not
  returned.
</ResponseField>

```json
{
  "id": "prod_abc123def456ghi789",
  "object": "product",
  "name": "JavaScript Course",
  "description": "Master JavaScript from A to Z",
  "type": "digital",
  "status": "active",
  "price": null,
  "category": 1,
  "subscriptionEligible": true,
  "prices": [
    {
      "id": "price_abc123def456ghi789",
      "productId": "prod_abc123def456ghi789",
      "amount": "25000.00",
      "currency": "xaf",
      "type": "one_time",
      "billingInterval": null,
      "billingIntervalCount": null,
      "trialPeriodDays": null,
      "active": true
    }
  ],
  "createdAt": "2024-01-15T10:30:00.000Z",
  "updatedAt": "2024-01-15T10:30:00.000Z"
}
```

## Common Operations

### Retrieve a Product

```bash
curl https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..."
```

### Update a Product

The verb is **`PUT`**, and the update is partial: only the fields present in the body are
changed.

```bash
curl -X PUT https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Advanced JavaScript Course",
    "description": "From beginner to expert in JavaScript"
  }'
```

<Note>
  Prices aren't updated here: they go through `POST /v1/prices` (new price) and
  `PUT /v1/prices/{id}` (activate/deactivate). See [Price
  Documentation](/en/products/prices).
</Note>

### Archive a Product

```bash
curl -X PUT https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "status": "archived"
  }'
```

### Delete a Product

<Warning>
  A deleted product is no longer visible, but the history of associated orders is kept.
</Warning>

```bash
curl -X DELETE https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..."
```

## Relations with Other Entities

```
Product
├── Price[] (prices attached to the product — productId)
├── Document[] (images, files)
└── ProductLink[] (related products)
    ├── Cross-sell (complementary products)
    ├── Upsell (higher-tier products)
    └── Related (associated products)
```

## Best Practices

<AccordionGroup>
  <Accordion title="Product Naming">
    - Use clear, descriptive names
    - Avoid obscure abbreviations
    - Include key characteristics in the name
  </Accordion>

  <Accordion title="Status Management">
    - Use `draft` for products being prepared
    - Only switch to `active` once everything is configured (pricing, images)
    - Archive rather than delete to keep the history
  </Accordion>

  <Accordion title="Catalog Organization">
    - Group similar products by category
    - Configure related products for cross-selling
  </Accordion>
</AccordionGroup>
