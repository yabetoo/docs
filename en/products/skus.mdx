## What is a SKU?

A **SKU** (Stock Keeping Unit) represents a specific variant of a product. For example, for a t-shirt, each size/color combination is a distinct SKU.

<Info>
  **Identifier format**: `sku_` followed by 36 alphanumeric characters.

  Example: `sku_abc123def456ghi789jkl012mno345`
</Info>

## Product → SKU Relationship

```
Product "Premium T-shirt"
├── SKU "T-shirt S White" (TSHIRT-S-WHITE)
├── SKU "T-shirt M White" (TSHIRT-M-WHITE)
├── SKU "T-shirt L White" (TSHIRT-L-WHITE)
├── SKU "T-shirt S Black" (TSHIRT-S-BLACK)
├── SKU "T-shirt M Black" (TSHIRT-M-BLACK)
└── SKU "T-shirt L Black" (TSHIRT-L-BLACK)
```

<Note>
  **SKUs are optional.** A product only needs variants when it really has variations. A SaaS
  plan or a service is a product without any SKU, whose price is attached directly to the
  product.
</Note>

<Warning>
  **Prices are not under SKUs anymore.** A price is attached to a **product** through
  `productId`. `skuId` — the link to a variant — is still accepted during the compatibility
  window but is **deprecated**. See [Pricing](/en/products/prices).
</Warning>

## SKU Attributes

### Main Attributes

| Attribute | Type | Description |
|-----------|------|-------------|
| `id` | string | Unique SKU identifier |
| `productId` | string | Reference to parent product |
| `skuCode` | string | Unique SKU code (e.g., "TSHIRT-S-WHITE") |
| `name` | string | Variant name |
| `attributes` | object | Variant attributes (size, color, etc.) |

### Inventory Management

| Attribute | Type | Description |
|-----------|------|-------------|
| `stockTracking` | boolean | Stock management enabled |
| `stockQuantity` | number \| null | Stock quantity (null if not tracked) |

## Create a SKU

### Simple SKU

```bash
curl -X POST https://api.yabetoo.com/v1/products/prod_abc123/skus \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "skuCode": "TSHIRT-M-WHITE",
    "name": "T-shirt M White",
    "attributes": {
      "size": "M",
      "color": "white"
    },
    "stockTracking": true,
    "stockQuantity": 100
  }'
```

### SKU without Stock Management

For digital products or services, disable stock tracking:

```bash
curl -X POST https://api.yabetoo.com/v1/products/prod_abc123/skus \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "skuCode": "COURSE-PRO",
    "name": "Pro Course",
    "attributes": {
      "access": "lifetime"
    },
    "stockTracking": false
  }'
```

<Note>
  Creating a SKU flips the parent product's `hasSkus` to `true`. You never set that field
  yourself — see [Products](/en/products/products).
</Note>

## API Response

```json
{
  "id": "sku_xyz789abc123def456",
  "productId": "prod_abc123def456ghi789",
  "skuCode": "TSHIRT-M-WHITE",
  "name": "T-shirt M White",
  "attributes": {
    "size": "M",
    "color": "white"
  },
  "stockTracking": true,
  "stockQuantity": 100,
  "createdAt": "2024-01-15T10:30:00.000Z",
  "updatedAt": "2024-01-15T10:30:00.000Z"
}
```

<Note>
  Read endpoints (`GET /v1/skus/{id}` and `GET /v1/products/{id}/skus`) add a `prices` array
  holding the SKU's **active** prices. `GET /v1/skus/{id}` also embeds the parent `product`.
</Note>

## Inventory Management

When `stockTracking` is enabled, the system automatically manages stock:

- **Pre-purchase verification**: Availability is checked before validating an order
- **Automatic update**: Stock is decremented upon purchase
- **Automatic restoration**: On cancellation or payment failure, stock is restored

<Tip>
  For digital products or services, disable `stockTracking` to allow unlimited sales.
</Tip>

## SKU Code

The `skuCode` is a unique, human-readable identifier for internal management:

<AccordionGroup>
  <Accordion title="Recommended naming conventions">
    | Pattern | Example | Description |
    |---------|---------|-------------|
    | `PRODUCT-SIZE-COLOR` | `TSHIRT-M-WHITE` | Standard for clothing |
    | `PRODUCT-OPTION1-OPTION2` | `PHONE-256GB-BLACK` | Electronics |
    | `CATEGORY-REF` | `BOOK-978123456` | Books with ISBN |
    | `SERVICE-PLAN` | `SAAS-PRO-MONTHLY` | Services/subscriptions |
  </Accordion>

  <Accordion title="Best practices">
    - Use alphanumeric characters and hyphens only
    - Keep codes short but descriptive
    - Avoid spaces and special characters
    - Be consistent in your naming convention
  </Accordion>
</AccordionGroup>

## Common Operations

### List SKUs for a product

```bash
curl https://api.yabetoo.com/v1/products/prod_abc123/skus \
  -H "Authorization: Bearer sk_live_..."
```

### Retrieve a SKU

```bash
curl https://api.yabetoo.com/v1/skus/sku_xyz789 \
  -H "Authorization: Bearer sk_live_..."
```

### Update a SKU

The verb is **`PUT`**, and the update is partial: only the fields present in the body are
changed. Editable fields are `name`, `attributes`, `stockTracking` and `stockQuantity` —
`skuCode` is not editable.

```bash
curl -X PUT https://api.yabetoo.com/v1/skus/sku_xyz789 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "stockQuantity": 150,
    "name": "T-shirt M White - Limited Edition"
  }'
```

<Note>
  **There is no dedicated stock endpoint.** Stock is updated through this same
  `PUT /v1/skus/{id}` by sending `stockQuantity`.
</Note>

### Delete a SKU

```bash
curl -X DELETE https://api.yabetoo.com/v1/skus/sku_xyz789 \
  -H "Authorization: Bearer sk_live_..."
```

<Warning>
  Deleting a SKU also deletes the prices attached to it. The call is refused with **409** while
  the SKU still has active inventory holds — wait for them to expire or be released. Once the
  last SKU of a product is gone, its `hasSkus` returns to `false`.
</Warning>

## SKUs and prices

A price is attached to the **product**, not to the variant. A SKU can still carry its own prices
through the deprecated `skuId`, which is how a per-variant price is expressed today:

```
Product "Premium T-shirt"
├── Price[]                            prices attached to the product
├── SKU "T-shirt S White" → Price[]    prices attached to the SKU (skuId, deprecated)
└── SKU "T-shirt M Black" → Price[]
```

<Note>
  Both scopes coexist. Creating a price only deactivates the active price of **its own scope**:
  a SKU price replaces the active price of *that* SKU, a product price replaces another
  product-level price. Two SKUs of the same product keep their own active prices.
</Note>

See [Price Documentation](/en/products/prices) to configure pricing.
