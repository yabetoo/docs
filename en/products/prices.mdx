## What is a Price?

A **Price** defines how a product is billed. It can be a one-time payment or a recurring subscription with different billing intervals.

<Info>
  **Identifier format**: `price_` followed by 36 alphanumeric characters.

  Example: `price_abc123def456ghi789jkl012mno345`
</Info>

## Product → Price Relationship

A price is attached to a **product**. `productId` is the canonical link, and a product can carry several prices for different pricing strategies:

```
Product "Pro Course"
├── Price 25,000 XAF one-time (single payment)
├── Price 5,000 XAF/month (monthly subscription)
├── Price 50,000 XAF/year (yearly subscription with savings)
└── Price 25,000 XOF one-time (West African market)
```

<Warning>
  **`skuId` is deprecated.** A price used to be attached to a SKU (a product variant).
  `skuId` is still accepted on `POST /v1/prices` during the compatibility window — the
  server then derives `productId` from the SKU — but it will be removed. New integrations
  must send `productId`. No removal date has been announced.
</Warning>

<Note>
  This flexibility allows you to offer multiple payment options for the same product and manage multiple currencies.
</Note>

## Price Attributes

### Main Attributes

| Attribute | Type | Description |
|-----------|------|-------------|
| `id` | string | Unique price identifier |
| `productId` | string | Reference to the parent product |
| `skuId` | string \| null | Reference to a SKU. Deprecated, and `null` for a price attached to the product |
| `amount` | string | Amount in the main unit of the currency, returned as a decimal string (`"25000.00"`) |
| `currency` | string | Currency code, returned in lowercase (`"xaf"`) |
| `type` | enum | `one_time` or `recurring` |
| `active` | boolean | Price active and usable |

### Recurring Attributes (subscriptions)

| Attribute | Type | Description |
|-----------|------|-------------|
| `billingInterval` | enum | `day`, `week`, `month`, `year` |
| `billingIntervalCount` | number | Number of intervals (e.g., 3 = every 3 months) |
| `trialPeriodDays` | number \| null | Free trial days |

## Create a Price

Prices are created on the collection endpoint `POST /v1/prices`, with the product they belong to in the body.

### Request body

<ParamField body="productId" type="string" required>
  Identifier of the product the price belongs to. Required unless the deprecated `skuId` is provided.
</ParamField>

<ParamField body="skuId" type="string" deprecated>
  Identifier of a SKU. Deprecated: when provided, the server derives `productId` from the SKU. Do not use in new integrations.
</ParamField>

<ParamField body="amount" type="number" required>
  Amount in the main unit of the currency. Must be strictly positive and at most `99999999.99`.
</ParamField>

<ParamField body="currency" type="string" default="XAF">
  Currency code, exactly 3 characters. Stored and returned in lowercase.
</ParamField>

<ParamField body="type" type="enum" default="one_time">
  `one_time` or `recurring`.
</ParamField>

<ParamField body="billingInterval" type="enum">
  `day`, `week`, `month` or `year`. Recurring prices only.
</ParamField>

<ParamField body="billingIntervalCount" type="number">
  Number of intervals per billing cycle. Must be strictly positive.
</ParamField>

<ParamField body="trialPeriodDays" type="number">
  Free trial days, `0` or more.
</ParamField>

<ParamField body="active" type="boolean" default="true">
  Set to `false` to create the price already deactivated.
</ParamField>

<Note>
  A product must exist before its price. Creating a product currently still requires at
  least one SKU in the payload — create the product with its SKU, then attach the price to
  the product with `productId`.
</Note>

<Warning>
  Creating a price **automatically deactivates** the price that was active for the same
  product, currency and type. Two recurring prices in the same currency on the same
  product (for example monthly and yearly) therefore cannot be active at the same time —
  use a separate product for each.
</Warning>

## Pricing Types

<Tabs>
  <Tab title="One-time payment">
    ### One-Time (`one_time`)

    The customer pays once to access the product.

    **Use cases:**
    - One-off purchases
    - Physical products
    - Digital downloads
    - Lifetime access

    ```bash
    curl -X POST https://api.yabetoo.com/v1/prices \
      -H "Authorization: Bearer sk_live_..." \
      -H "Content-Type: application/json" \
      -d '{
        "productId": "prod_abc123",
        "amount": 25000,
        "currency": "XAF",
        "type": "one_time"
      }'
    ```
  </Tab>

  <Tab title="Recurring subscription">
    ### Recurring (`recurring`)

    The customer is billed automatically at regular intervals.

    **Use cases:**
    - SaaS subscriptions
    - Ongoing services
    - Premium access
    - Maintenance

    ```bash
    curl -X POST https://api.yabetoo.com/v1/prices \
      -H "Authorization: Bearer sk_live_..." \
      -H "Content-Type: application/json" \
      -d '{
        "productId": "prod_abc123",
        "amount": 5000,
        "currency": "XAF",
        "type": "recurring",
        "billingInterval": "month",
        "billingIntervalCount": 1,
        "trialPeriodDays": 14
      }'
    ```
  </Tab>
</Tabs>

## Billing Intervals

For recurring prices, define the billing frequency:

| Interval | Count | Description | Example |
|----------|-------|-------------|---------|
| `day` | 1 | Daily | Billed every day |
| `week` | 1 | Weekly | Billed every week |
| `week` | 2 | Bi-weekly | Billed every 2 weeks |
| `month` | 1 | Monthly | Billed every month |
| `month` | 3 | Quarterly | Billed every 3 months |
| `month` | 6 | Semi-annual | Billed every 6 months |
| `year` | 1 | Annual | Billed every year |

```json
// Quarterly billing
{
  "productId": "prod_abc123",
  "type": "recurring",
  "billingInterval": "month",
  "billingIntervalCount": 3,
  "amount": 15000
}
```

## Trial Periods

Offer a free trial period to attract new customers:

```json
{
  "productId": "prod_abc123",
  "type": "recurring",
  "billingInterval": "month",
  "billingIntervalCount": 1,
  "amount": 9000,
  "currency": "XAF",
  "trialPeriodDays": 14
}
```

<Steps>
  <Step title="Subscription start">
    Customer signs up and starts their free trial period
  </Step>
  <Step title="Trial period">
    For 14 days, customer has full access without being charged
  </Step>
  <Step title="Trial end">
    At the end of the trial period, the first payment is automatically charged
  </Step>
  <Step title="Recurring cycle">
    Subsequent payments are charged according to the defined interval
  </Step>
</Steps>

<Warning>
  Make sure to clearly inform your customers about the trial duration and the amount that will be charged afterward.
</Warning>

## Multi-Currency Management

Create multiple prices for the same product in different currencies. Each price is a separate `POST /v1/prices` call:

```json
{
  "productId": "prod_abc123",
  "prices": [
    {
      "amount": 25000,
      "currency": "XAF",
      "type": "one_time"
    },
    {
      "amount": 25000,
      "currency": "XOF",
      "type": "one_time"
    },
    {
      "amount": 39,
      "currency": "EUR",
      "type": "one_time"
    }
  ]
}
```

### Supported Currencies

| Code | Currency | Country/Region |
|------|----------|----------------|
| `XAF` | CFA Franc BEAC | Central Africa |
| `XOF` | CFA Franc BCEAO | West Africa |
| `GNF` | Guinean Franc | Guinea |
| `CDF` | Congolese Franc | DR Congo |
| `EUR` | Euro | Europe |
| `USD` | US Dollar | United States |

<Note>
  When `currency` is omitted, the price is created in **XAF**, the default currency.
</Note>

<Tip>
  All amounts are expressed in the main unit of the currency, never in cents. For example: 25000 XAF = 25,000 XAF, 39 EUR = €39.
</Tip>

## API Response

The price object exposes `product` and `sku` **side by side**, at the root of the object. There is no nested `sku.product` anymore.

<ResponseField name="productId" type="string">
  Identifier of the parent product.
</ResponseField>

<ResponseField name="product" type="object">
  The parent product, always present.
</ResponseField>

<ResponseField name="skuId" type="string | null">
  Deprecated. `null` when the price is attached to the product.
</ResponseField>

<ResponseField name="sku" type="object | null">
  The SKU the price came from, or **`null`** when the price is attached to the product.
</ResponseField>

<Warning>
  **`price.sku` can be `null`.** Any integration that reads `price.sku.product` — or
  dereferences `price.sku` at all — must guard against `null`, otherwise it breaks as soon
  as a price is attached to a product. Read the product from `price.product` or
  `price.productId`.
</Warning>

## Common Operations

### Create a price

```bash
curl -X POST https://api.yabetoo.com/v1/prices \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "productId": "prod_abc123",
    "amount": 9000,
    "currency": "XAF",
    "type": "recurring",
    "billingInterval": "month",
    "billingIntervalCount": 1
  }'
```

### Retrieve a price

```bash
curl https://api.yabetoo.com/v1/prices/price_abc123 \
  -H "Authorization: Bearer sk_live_..."
```

### List the prices of a product

```bash
curl "https://api.yabetoo.com/v1/prices?productId=prod_abc123" \
  -H "Authorization: Bearer sk_live_..."
```

`GET /v1/prices` accepts the following filters, which can be combined:

| Filter | Description |
|--------|-------------|
| `productId` | Only the prices of this product |
| `skuId` | Only the prices of this SKU. Deprecated, like the field itself |
| `type` | `one_time` or `recurring` |
| `active` | `true` or `false` |

### Deactivate a price

<Note>
  Prices cannot be deleted if they are associated with active subscriptions. Use deactivation instead.
</Note>

```bash
curl -X PUT https://api.yabetoo.com/v1/prices/price_abc123 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "active": false
  }'
```

## Pricing Strategies

### Monthly vs Annual Offer

Offer a discount for annual subscription:

```json
{
  "prices": [
    {
      "productId": "prod_saas_pro_monthly",
      "amount": 9000,
      "currency": "XAF",
      "type": "recurring",
      "billingInterval": "month",
      "billingIntervalCount": 1
    },
    {
      "productId": "prod_saas_pro_yearly",
      "amount": 90000,
      "currency": "XAF",
      "type": "recurring",
      "billingInterval": "year",
      "billingIntervalCount": 1
    }
  ]
}
```

<Tip>
  9,000 XAF/month vs 90,000 XAF/year represents about 2 free months, which encourages customers to commit for the year.
</Tip>

<Note>
  The two prices belong to two distinct products: a single product cannot hold two active
  recurring prices in the same currency, since the second one deactivates the first.
</Note>

### Tiered Pricing

Create one product per service level, each with its own price:

```
Product "Cloud App — Starter"     → Price 5,000 XAF/month
Product "Cloud App — Pro"         → Price 15,000 XAF/month
Product "Cloud App — Enterprise"  → Price 50,000 XAF/month
```

## Useful Getters

The Price model provides getters to facilitate checks:

```typescript
// Check price type
price.isRecurring  // true if type === 'recurring'
price.isOneTime    // true if type === 'one_time'
```

## Best Practices

<AccordionGroup>
  <Accordion title="Amount format">
    Amounts are expressed in the main unit of the currency, never in cents:
    - XAF: 25000 = 25,000 XAF
    - XOF: 25000 = 25,000 XOF
    - EUR: 39 = €39

    Decimals are allowed, and the amount cannot exceed `99999999.99`. The API returns it as a decimal string (`"25000.00"`).
  </Accordion>

  <Accordion title="Attaching a price">
    - Always send `productId`: it is the canonical link
    - `skuId` only remains for existing integrations, and is deprecated
    - Read the product from `price.product`, never from `price.sku.product`
  </Accordion>

  <Accordion title="Active/inactive prices">
    - Deactivate old prices rather than deleting them
    - Keep active prices to the minimum necessary
    - Remember that a new price deactivates the active price with the same product, currency and type
  </Accordion>

  <Accordion title="Trial periods">
    - 7 to 14 days is generally optimal
    - Too short: not enough time to evaluate
    - Too long: potential revenue loss
  </Accordion>

  <Accordion title="Multi-currency">
    - Adjust prices for each market (not simple conversion)
    - Consider local purchasing power
    - Use psychological pricing (9,000 XAF rather than 8,750 XAF)
  </Accordion>
</AccordionGroup>
