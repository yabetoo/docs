## Qu'est-ce qu'un Produit ?

Un **Produit** représente un article ou service que vous vendez. C'est l'entité de base de votre catalogue autour de laquelle s'articulent les variantes (SKUs), les prix et les promotions.

Les prix et les variantes se rattachent au produit en **deux branches parallèles** : un prix est
rattaché au produit via `productId`, et les variantes sont optionnelles. Un plan SaaS ou une
prestation de service est donc un produit avec des prix et aucun SKU.

<Info>
  **Format de l'identifiant** : `prod_` suivi de 36 caractères alphanumériques.

  Exemple : `prod_abc123def456ghi789jkl012mno345`
</Info>

## Attributs du Produit

### Attributs principaux

| Attribut | Type | Description |
|----------|------|-------------|
| `id` | string | Identifiant unique du produit |
| `name` | string | Nom du produit affiché aux clients |
| `description` | string | Description détaillée du produit |
| `type` | enum | Type de produit : `physical`, `digital`, `service` |
| `status` | enum | Statut : `active`, `archived`, `draft` |
| `price` | number \| null | Prix par défaut (optionnel) |
| `category` | number | Catégorie du produit |
| `subscriptionEligible` | boolean | Peut être vendu en abonnement |
| `hasSkus` | boolean | Indique si le produit a des variantes. **En lecture seule** : dérivé des SKU réellement existants, jamais envoyé par l'appelant |
| `skus` | array | Les variantes du produit. Vide pour un produit sans SKU |
| `prices` | array | Les prix **actifs** rattachés au produit. Les prix rattachés à un SKU restent sous `skus[].prices` |

## Types de produits

<Tabs>
  <Tab title="Physique">
    ### Produit Physique (`physical`)

    Un produit tangible qui nécessite une livraison au client.

    **Caractéristiques :**
    - Gestion du stock activée
    - Adresse de livraison requise
    - Suivi des expéditions possible

    **Exemples :** Vêtements, électronique, livres imprimés, accessoires

    ```json
    {
      "name": "T-shirt Premium",
      "type": "physical",
      "description": "T-shirt 100% coton biologique"
    }
    ```
  </Tab>

  <Tab title="Numérique">
    ### Produit Numérique (`digital`)

    Un produit dématérialisé accessible par téléchargement.

    **Caractéristiques :**
    - Livraison instantanée après paiement
    - Liens de téléchargement sécurisés
    - Contrôle du nombre de téléchargements
    - Expiration des liens possible

    **Exemples :** E-books, logiciels, formations vidéo, templates

    ```json
    {
      "name": "Formation React Avancé",
      "type": "digital",
      "description": "20 heures de vidéo + ressources",
      "subscriptionEligible": false
    }
    ```
  </Tab>

  <Tab title="Service">
    ### Service (`service`)

    Une prestation de service ponctuelle ou continue.

    **Caractéristiques :**
    - Pas de stock physique
    - Idéal pour les abonnements
    - Facturation récurrente possible

    **Exemples :** Consultations, abonnements SaaS, maintenance, coaching

    ```json
    {
      "name": "Abonnement Pro",
      "type": "service",
      "description": "Accès illimité à toutes les fonctionnalités",
      "subscriptionEligible": true
    }
    ```
  </Tab>
</Tabs>

## Statuts du produit

Le statut détermine la visibilité et la disponibilité du produit :

<CardGroup cols={3}>
  <Card title="Active" icon="circle-check" color="#22c55e">
    Le produit est visible et disponible à la vente. Les clients peuvent l'acheter.
  </Card>
  <Card title="Draft" icon="pencil" color="#f59e0b">
    Brouillon en cours de création. Non visible par les clients.
  </Card>
  <Card title="Archived" icon="box-archive" color="#6b7280">
    Produit archivé. Non visible mais conservé pour l'historique.
  </Card>
</CardGroup>

```typescript
enum ProductStatus {
  ACTIVE = 'active',      // Disponible à la vente
  DRAFT = 'draft',        // En cours de création
  ARCHIVED = 'archived'   // Archivé
}
```

## Créer un produit

Les produits se créent sur `POST /v1/products`.

### Corps de la requête

<ParamField body="name" type="string" required>
  Nom du produit, de 3 à 70 caractères.
</ParamField>

<ParamField body="description" type="string" required>
  Description du produit, de 10 à 255 caractères.
</ParamField>

<ParamField body="type" type="enum" required>
  `physical`, `digital` ou `service`.
</ParamField>

<ParamField body="category" type="number" required>
  Catégorie du produit, strictement positive.
</ParamField>

<ParamField body="subscriptionEligible" type="boolean" required>
  Indique si le produit peut être vendu en abonnement.
</ParamField>

<ParamField body="accountId" type="string" required>
  Identifiant du compte auquel le produit appartient. Il doit correspondre au compte de la clé
  API — toute autre valeur est refusée.
</ParamField>

<ParamField body="status" type="enum" default="draft">
  `active`, `draft` ou `archived`.
</ParamField>

<ParamField body="skus" type="array">
  Les variantes du produit, chacune avec son `price`. **Optionnel** : omettez-le pour un produit
  sans variante.
</ParamField>

<Note>
  `hasSkus` n'est **pas** un champ que vous envoyez. Le serveur le dérive des variantes
  réellement existantes, et le tient à jour quand un SKU est ajouté ou supprimé.
</Note>

<Warning>
  **Omettre `skus` est permis, envoyer `skus: []` ne l'est pas.** Un produit sans variante — un
  plan SaaS, une prestation — se crée en laissant le champ de côté. Un tableau vide explicite
  est refusé en **422** (`The skus field must have at least 1 items`) : c'est presque toujours
  un bug d'appelant (un formulaire qui sérialise une liste vide), et l'accepter en silence
  produirait le même produit qu'une omission tout en masquant l'erreur.
</Warning>

<Steps>
  <Step title="Créer le produit">
    Un produit sans variante — son prix est rattaché ensuite avec `productId`.

    ```bash
    curl -X POST https://api.yabetoo.com/v1/products \
      -H "Authorization: Bearer sk_live_..." \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Formation JavaScript",
        "description": "Maîtrisez JavaScript de A à Z",
        "type": "digital",
        "category": 1,
        "subscriptionEligible": false,
        "accountId": "acct_abc123"
      }'
    ```
  </Step>

  <Step title="Ajouter les variantes (optionnel)">
    Uniquement pour les produits qui ont réellement des déclinaisons (taille, couleur, plan…).
    Chaque variante se crée en ligne via `skus`, ou plus tard sur
    `POST /v1/products/{id}/skus`.

    Voir [Documentation des SKUs](/fr/products/skus)
  </Step>

  <Step title="Définir les prix">
    Rattachez un ou plusieurs prix au produit avec `POST /v1/prices` et `productId`.

    Voir [Documentation des Prix](/fr/products/prices)
  </Step>
</Steps>

### Créer avec les variantes en ligne

Lorsque `skus` est fourni, chaque entrée **exige** un `price`, dont la `currency` est limitée à
`eur` ou `xaf` sur cet endpoint :

```bash
curl -X POST https://api.yabetoo.com/v1/products \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "T-shirt Premium",
    "description": "T-shirt 100% coton biologique",
    "type": "physical",
    "category": 2,
    "subscriptionEligible": false,
    "accountId": "acct_abc123",
    "skus": [
      {
        "skuCode": "TSHIRT-M-WHITE",
        "name": "T-shirt M Blanc",
        "attributes": { "size": "M", "color": "white" },
        "stockTracking": true,
        "stockQuantity": 100,
        "price": {
          "amount": 15000,
          "currency": "xaf",
          "type": "one_time"
        }
      }
    ]
  }'
```

## Réponse API

`GET /v1/products` et `GET /v1/products/{id}` exposent les deux branches côte à côte.

<ResponseField name="skus" type="array">
  Les variantes du produit, chacune portant ses prix actifs sous `skus[].prices`.
</ResponseField>

<ResponseField name="prices" type="array">
  Les prix rattachés **directement au produit** (`skuId` à null). **Prix actifs uniquement** —
  les prix désactivés ne sont pas renvoyés.
</ResponseField>

<Note>
  Les deux listes ne se recouvrent jamais : un prix rattaché à un SKU apparaît sous
  `skus[].prices` et **jamais** dans le `prices` de niveau produit. Les additionner est donc
  sans risque.
</Note>

<Warning>
  Un prix de SKU porte lui aussi `productId` — il a été backfillé sur **tous** les prix.
  N'utilisez pas `productId` seul pour distinguer un prix de niveau produit d'un prix de SKU :
  le discriminant est `skuId`, qui ne vaut `null` que pour les prix de niveau produit.
</Warning>

## Opérations courantes

### Récupérer un produit

```bash
curl https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..."
```

### Mettre à jour un produit

Le verbe est **`PUT`**, et la mise à jour est partielle : seuls les champs présents dans le
corps sont modifiés.

```bash
curl -X PUT https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Formation JavaScript Avancé",
    "description": "De débutant à expert en JavaScript"
  }'
```

<Note>
  `skus` et `prices` ne se modifient pas ici. Les variantes passent par les endpoints SKU, les
  prix par `POST /v1/prices` et `PUT /v1/prices/{id}`.
</Note>

### Archiver un produit

```bash
curl -X PUT https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "status": "archived"
  }'
```

### Supprimer un produit

<Warning>
  Un produit supprimé n'est plus visible mais l'historique des commandes associées est conservé.
</Warning>

```bash
curl -X DELETE https://api.yabetoo.com/v1/products/prod_abc123 \
  -H "Authorization: Bearer sk_live_..."
```

## Relations avec d'autres entités

```
Product
├── Price[] (prix rattachés au produit — productId)
├── ProductSku[] (variantes)
│   └── Price[] (prix rattachés à un SKU — skuId, déprécié)
├── Document[] (images, fichiers)
└── ProductLink[] (produits liés)
    ├── Cross-sell (produits complémentaires)
    ├── Upsell (produits supérieurs)
    └── Related (produits associés)
```

`Price[]` et `ProductSku[]` sont **deux branches parallèles** du produit, et non l'une imbriquée
dans l'autre. Un prix pointe encore vers un SKU tant que `skuId` existe, mais ce lien est
[déprécié](/fr/products/prices).

## Bonnes pratiques

<AccordionGroup>
  <Accordion title="Nommage des produits">
    - Utilisez des noms clairs et descriptifs
    - Évitez les abréviations obscures
    - Incluez les caractéristiques clés dans le nom pour les variantes
  </Accordion>

  <Accordion title="Gestion des statuts">
    - Utilisez `draft` pour les produits en préparation
    - Passez en `active` uniquement quand tout est configuré (prix, images, stock)
    - Archivez plutôt que supprimer pour conserver l'historique
  </Accordion>

  <Accordion title="Organisation du catalogue">
    - Groupez les produits similaires par catégorie
    - Utilisez les variantes (SKUs) pour les déclinaisons d'un même produit
    - Un produit qui n'a rien à décliner — un plan SaaS, une prestation — n'a besoin d'aucun
      SKU : rattachez son prix directement au produit
    - Configurez les produits liés pour le cross-selling
  </Accordion>
</AccordionGroup>
