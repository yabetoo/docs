## Qu'est-ce qu'un SKU ?

Un **SKU** (Stock Keeping Unit) représente une variante spécifique d'un produit. Par exemple, pour un t-shirt, chaque combinaison taille/couleur est un SKU distinct.

<Info>
  **Format de l'identifiant** : `sku_` suivi de 36 caractères alphanumériques.

  Exemple : `sku_abc123def456ghi789jkl012mno345`
</Info>

## Relation Produit → SKU

```
Produit "T-shirt Premium"
├── SKU "T-shirt S Blanc" (TSHIRT-S-WHITE)
├── SKU "T-shirt M Blanc" (TSHIRT-M-WHITE)
├── SKU "T-shirt L Blanc" (TSHIRT-L-WHITE)
├── SKU "T-shirt S Noir" (TSHIRT-S-BLACK)
├── SKU "T-shirt M Noir" (TSHIRT-M-BLACK)
└── SKU "T-shirt L Noir" (TSHIRT-L-BLACK)
```

<Note>
  **Les SKU sont optionnels.** Un produit n'a besoin de variantes que s'il a réellement des
  déclinaisons. Un plan SaaS ou une prestation de service est un produit sans aucun SKU, dont le
  prix est rattaché directement au produit.
</Note>

<Warning>
  **Les prix ne sont plus sous les SKU.** Un prix est rattaché à un **produit** via `productId`.
  `skuId` — le lien vers une variante — reste accepté pendant la fenêtre de compatibilité mais
  il est **déprécié**. Voir [Tarification](/fr/products/prices).
</Warning>

## Attributs du SKU

### Attributs principaux

| Attribut | Type | Description |
|----------|------|-------------|
| `id` | string | Identifiant unique du SKU |
| `productId` | string | Référence au produit parent |
| `skuCode` | string | Code unique du SKU (ex: "TSHIRT-S-WHITE") |
| `name` | string | Nom de la variante |
| `attributes` | object | Attributs de la variante (taille, couleur, etc.) |

### Gestion du stock

| Attribut | Type | Description |
|----------|------|-------------|
| `stockTracking` | boolean | Gestion du stock activée |
| `stockQuantity` | number \| null | Quantité en stock (null si non suivi) |

## Créer un SKU

### SKU simple

```bash
curl -X POST https://api.yabetoo.com/v1/products/prod_abc123/skus \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "skuCode": "TSHIRT-M-WHITE",
    "name": "T-shirt M Blanc",
    "attributes": {
      "size": "M",
      "color": "white"
    },
    "stockTracking": true,
    "stockQuantity": 100
  }'
```

### SKU sans gestion de stock

Pour les produits numériques ou services, désactivez le suivi du stock :

```bash
curl -X POST https://api.yabetoo.com/v1/products/prod_abc123/skus \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "skuCode": "FORMATION-PRO",
    "name": "Formation Pro",
    "attributes": {
      "access": "lifetime"
    },
    "stockTracking": false
  }'
```

<Note>
  La création d'un SKU bascule le `hasSkus` du produit parent à `true`. Vous ne renseignez
  jamais ce champ vous-même — voir [Produits](/fr/products/products).
</Note>

## Réponse API

```json
{
  "id": "sku_xyz789abc123def456",
  "productId": "prod_abc123def456ghi789",
  "skuCode": "TSHIRT-M-WHITE",
  "name": "T-shirt M Blanc",
  "attributes": {
    "size": "M",
    "color": "white"
  },
  "stockTracking": true,
  "stockQuantity": 100,
  "createdAt": "2024-01-15T10:30:00.000Z",
  "updatedAt": "2024-01-15T10:30:00.000Z"
}
```

<Note>
  Les endpoints de lecture (`GET /v1/skus/{id}` et `GET /v1/products/{id}/skus`) ajoutent un
  tableau `prices` contenant les prix **actifs** du SKU. `GET /v1/skus/{id}` embarque en plus le
  `product` parent.
</Note>

## Gestion du stock

Lorsque `stockTracking` est activé, le système gère automatiquement le stock :

- **Vérification avant achat** : La disponibilité est vérifiée avant de valider une commande
- **Mise à jour automatique** : Le stock est décrémenté lors d'un achat
- **Restauration automatique** : En cas d'annulation ou d'échec de paiement, le stock est restauré

<Tip>
  Pour les produits numériques ou services, désactivez `stockTracking` pour permettre des ventes illimitées.
</Tip>

## Code SKU

Le `skuCode` est un identifiant unique et lisible par l'humain pour la gestion interne :

<AccordionGroup>
  <Accordion title="Conventions de nommage recommandées">
    | Pattern | Exemple | Description |
    |---------|---------|-------------|
    | `PRODUIT-TAILLE-COULEUR` | `TSHIRT-M-WHITE` | Standard pour vêtements |
    | `PRODUIT-OPTION1-OPTION2` | `PHONE-256GB-BLACK` | Électronique |
    | `CATEGORIE-REF` | `BOOK-978123456` | Livres avec ISBN |
    | `SERVICE-PLAN` | `SAAS-PRO-MONTHLY` | Services/abonnements |
  </Accordion>

  <Accordion title="Bonnes pratiques">
    - Utilisez des caractères alphanumériques et tirets uniquement
    - Gardez les codes courts mais descriptifs
    - Évitez les espaces et caractères spéciaux
    - Soyez cohérent dans votre nomenclature
  </Accordion>
</AccordionGroup>

## Opérations courantes

### Lister les SKUs d'un produit

```bash
curl https://api.yabetoo.com/v1/products/prod_abc123/skus \
  -H "Authorization: Bearer sk_live_..."
```

### Récupérer un SKU

```bash
curl https://api.yabetoo.com/v1/skus/sku_xyz789 \
  -H "Authorization: Bearer sk_live_..."
```

### Mettre à jour un SKU

Le verbe est **`PUT`**, et la mise à jour est partielle : seuls les champs présents dans le
corps sont modifiés. Les champs modifiables sont `name`, `attributes`, `stockTracking` et
`stockQuantity` — `skuCode` n'est pas modifiable.

```bash
curl -X PUT https://api.yabetoo.com/v1/skus/sku_xyz789 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "stockQuantity": 150,
    "name": "T-shirt M Blanc - Édition Limitée"
  }'
```

<Note>
  **Il n'existe pas d'endpoint dédié au stock.** Le stock se met à jour par ce même
  `PUT /v1/skus/{id}`, en envoyant `stockQuantity`.
</Note>

### Supprimer un SKU

```bash
curl -X DELETE https://api.yabetoo.com/v1/skus/sku_xyz789 \
  -H "Authorization: Bearer sk_live_..."
```

<Warning>
  Supprimer un SKU supprime aussi les prix qui lui sont rattachés. L'appel est refusé en **409**
  tant que le SKU porte des réservations de stock actives — attendez leur expiration ou leur
  libération. Une fois le dernier SKU d'un produit supprimé, son `hasSkus` repasse à `false`.
</Warning>

## SKU et prix

Un prix est rattaché au **produit**, pas à la variante. Un SKU peut encore porter ses propres
prix via le `skuId` déprécié, qui est aujourd'hui la façon d'exprimer un prix par variante :

```
Produit "T-shirt Premium"
├── Price[]                             prix rattachés au produit
├── SKU "T-shirt S Blanc" → Price[]     prix rattachés au SKU (skuId, déprécié)
└── SKU "T-shirt M Noir"  → Price[]
```

<Note>
  Les deux portées coexistent. La création d'un prix ne désactive que le prix actif de **sa
  propre portée** : un prix de SKU remplace le prix actif de *ce* SKU, un prix de produit
  remplace un autre prix de niveau produit. Deux SKU d'un même produit gardent chacun leur prix
  actif.
</Note>

Voir [Documentation des Prix](/fr/products/prices) pour configurer la tarification.
