## Qu'est-ce qu'un Price ?

Un **Price** (Prix) définit comment un produit est facturé. Il peut s'agir d'un paiement unique ou d'un abonnement récurrent avec différentes périodicités.

<Info>
  **Format de l'identifiant** : `price_` suivi de 36 caractères alphanumériques.

  Exemple : `price_abc123def456ghi789jkl012mno345`
</Info>

## Relation Produit → Price

Un prix est rattaché à un **produit**. `productId` est le lien canonique, et un produit peut porter plusieurs prix pour différentes stratégies tarifaires :

```
Produit "Formation Pro"
├── Price 25 000 XAF one-time (paiement unique)
├── Price 5 000 XAF/mois (abonnement mensuel)
├── Price 50 000 XAF/an (abonnement annuel avec économie)
└── Price 25 000 XOF one-time (marché ouest-africain)
```

<Warning>
  **`skuId` est déprécié.** Un prix était auparavant rattaché à un SKU (une variante de
  produit). `skuId` reste accepté sur `POST /v1/prices` pendant la fenêtre de
  compatibilité — le serveur en déduit alors `productId` — mais il sera retiré. Les
  nouvelles intégrations doivent envoyer `productId`. Aucune date de retrait n'est annoncée.
</Warning>

<Note>
  Cette flexibilité permet de proposer plusieurs options de paiement pour le même produit et de gérer plusieurs devises.
</Note>

## Attributs du Price

### Attributs principaux

| Attribut | Type | Description |
|----------|------|-------------|
| `id` | string | Identifiant unique du prix |
| `productId` | string | Référence au produit parent |
| `skuId` | string \| null | Référence à un SKU. Déprécié, et `null` pour un prix rattaché au produit |
| `amount` | string | Montant dans l'unité principale de la devise, renvoyé sous forme de chaîne décimale (`"25000.00"`) |
| `currency` | string | Code devise, renvoyé en minuscules (`"xaf"`) |
| `type` | enum | `one_time` ou `recurring` |
| `active` | boolean | Prix actif et utilisable |

### Attributs récurrents (abonnements)

| Attribut | Type | Description |
|----------|------|-------------|
| `billingInterval` | enum | `day`, `week`, `month`, `year` |
| `billingIntervalCount` | number | Nombre d'intervalles (ex: 3 = tous les 3 mois) |
| `trialPeriodDays` | number \| null | Jours d'essai gratuit |

## Créer un prix

Les prix se créent sur l'endpoint de collection `POST /v1/prices`, en indiquant dans le corps le produit auquel ils se rattachent.

### Corps de la requête

<ParamField body="productId" type="string" required>
  Identifiant du produit auquel le prix se rattache. Obligatoire, sauf si le champ déprécié `skuId` est fourni.
</ParamField>

<ParamField body="skuId" type="string" deprecated>
  Identifiant d'un SKU. Déprécié : lorsqu'il est fourni, le serveur en déduit `productId`. À ne plus utiliser dans une nouvelle intégration.
</ParamField>

<ParamField body="amount" type="number" required>
  Montant dans l'unité principale de la devise. Strictement positif et au maximum `99999999.99`.
</ParamField>

<ParamField body="currency" type="string" default="XAF">
  Code devise, exactement 3 caractères. Stocké et renvoyé en minuscules.
</ParamField>

<ParamField body="type" type="enum" default="one_time">
  `one_time` ou `recurring`.
</ParamField>

<ParamField body="billingInterval" type="enum">
  `day`, `week`, `month` ou `year`. Prix récurrents uniquement.
</ParamField>

<ParamField body="billingIntervalCount" type="number">
  Nombre d'intervalles par cycle de facturation. Strictement positif.
</ParamField>

<ParamField body="trialPeriodDays" type="number">
  Jours d'essai gratuit, `0` ou plus.
</ParamField>

<ParamField body="active" type="boolean" default="true">
  Passez `false` pour créer le prix déjà désactivé.
</ParamField>

<Note>
  Le produit doit exister avant son prix. Il n'a besoin d'aucun SKU : omettez `skus` à la
  création du produit — c'est ainsi qu'on modélise un plan SaaS ou un service — puis
  rattachez le prix au produit avec `productId`. À noter qu'un tableau `skus: []`
  explicitement vide reste refusé avec un `422`.
</Note>

<Warning>
  La création d'un prix **désactive automatiquement** le prix qui était actif pour le même
  produit, la même devise, le même type **et la même portée**. La portée, c'est : un prix
  rattaché à un SKU ne remplace que le prix actif de *ce SKU-là*, et un prix rattaché
  directement au produit ne remplace qu'un autre prix de niveau produit. Deux SKU d'un même
  produit gardent chacun leur prix actif.

  À en retenir la conséquence : un prix mensuel et un prix annuel partagent le même `type`
  (`recurring`), donc au sein d'une même portée le second désactive le premier. Pour
  proposer les deux, rattachez-les à deux SKU différents, ou utilisez un produit distinct
  pour chacun.
</Warning>

## Types de tarification

<Tabs>
  <Tab title="Paiement unique">
    ### One-Time (`one_time`)

    Le client paie une seule fois pour accéder au produit.

    **Cas d'usage :**
    - Achats ponctuels
    - Produits physiques
    - Téléchargements numériques
    - Accès à vie

    ```bash
    curl -X POST https://api.yabetoo.com/v1/prices \
      -H "Authorization: Bearer sk_live_..." \
      -H "Content-Type: application/json" \
      -d '{
        "productId": "prod_abc123",
        "amount": 25000,
        "currency": "XAF",
        "type": "one_time"
      }'
    ```
  </Tab>

  <Tab title="Abonnement récurrent">
    ### Recurring (`recurring`)

    Le client est facturé automatiquement à intervalles réguliers.

    **Cas d'usage :**
    - Abonnements SaaS
    - Services continus
    - Accès premium
    - Maintenance

    ```bash
    curl -X POST https://api.yabetoo.com/v1/prices \
      -H "Authorization: Bearer sk_live_..." \
      -H "Content-Type: application/json" \
      -d '{
        "productId": "prod_abc123",
        "amount": 5000,
        "currency": "XAF",
        "type": "recurring",
        "billingInterval": "month",
        "billingIntervalCount": 1,
        "trialPeriodDays": 14
      }'
    ```
  </Tab>
</Tabs>

## Intervalles de facturation

Pour les prix récurrents, définissez la fréquence de facturation :

| Interval | Count | Description | Exemple |
|----------|-------|-------------|---------|
| `day` | 1 | Quotidien | Facturé chaque jour |
| `week` | 1 | Hebdomadaire | Facturé chaque semaine |
| `week` | 2 | Bi-hebdomadaire | Facturé toutes les 2 semaines |
| `month` | 1 | Mensuel | Facturé chaque mois |
| `month` | 3 | Trimestriel | Facturé tous les 3 mois |
| `month` | 6 | Semestriel | Facturé tous les 6 mois |
| `year` | 1 | Annuel | Facturé chaque année |

```json
// Facturation trimestrielle
{
  "productId": "prod_abc123",
  "type": "recurring",
  "billingInterval": "month",
  "billingIntervalCount": 3,
  "amount": 15000
}
```

## Périodes d'essai

Offrez une période d'essai gratuit pour attirer de nouveaux clients :

```json
{
  "productId": "prod_abc123",
  "type": "recurring",
  "billingInterval": "month",
  "billingIntervalCount": 1,
  "amount": 9000,
  "currency": "XAF",
  "trialPeriodDays": 14
}
```

<Steps>
  <Step title="Début de l'abonnement">
    Le client s'inscrit et démarre sa période d'essai gratuite
  </Step>
  <Step title="Période d'essai">
    Pendant 14 jours, le client a accès complet sans être facturé
  </Step>
  <Step title="Fin de l'essai">
    À la fin de la période d'essai, le premier paiement est prélevé automatiquement
  </Step>
  <Step title="Cycle récurrent">
    Les paiements suivants sont prélevés selon l'intervalle défini
  </Step>
</Steps>

<Warning>
  Assurez-vous d'informer clairement vos clients sur la durée de l'essai et le montant qui sera facturé après.
</Warning>

## Gestion multi-devises

Créez plusieurs prix pour le même produit dans différentes devises. Chaque prix correspond à un appel `POST /v1/prices` distinct :

```json
{
  "productId": "prod_abc123",
  "prices": [
    {
      "amount": 25000,
      "currency": "XAF",
      "type": "one_time"
    },
    {
      "amount": 25000,
      "currency": "XOF",
      "type": "one_time"
    },
    {
      "amount": 39,
      "currency": "EUR",
      "type": "one_time"
    }
  ]
}
```

### Devises supportées

| Code | Devise | Pays/Région |
|------|--------|-------------|
| `XAF` | Franc CFA BEAC | Afrique Centrale |
| `XOF` | Franc CFA BCEAO | Afrique de l'Ouest |
| `GNF` | Franc guinéen | Guinée |
| `CDF` | Franc congolais | RD Congo |
| `EUR` | Euro | Europe |
| `USD` | Dollar américain | États-Unis |

<Note>
  Lorsque `currency` est omis, le prix est créé en **XAF**, la devise par défaut.
</Note>

<Tip>
  Tous les montants sont exprimés dans l'unité principale de la devise, jamais en centimes. Par exemple : 25000 XAF = 25 000 XAF, 39 EUR = 39 €.
</Tip>

## Réponse API

L'objet price expose `product` et `sku` **côte à côte**, à la racine de l'objet. Il n'y a plus de `sku.product` imbriqué.

<ResponseField name="productId" type="string">
  Identifiant du produit parent.
</ResponseField>

<ResponseField name="product" type="object">
  Le produit parent, toujours présent.
</ResponseField>

<ResponseField name="skuId" type="string | null">
  Déprécié. Vaut `null` lorsque le prix est rattaché au produit.
</ResponseField>

<ResponseField name="sku" type="object | null">
  Le SKU dont provient le prix, ou **`null`** lorsque le prix est rattaché au produit.
</ResponseField>

<Warning>
  **`price.sku` peut valoir `null`.** Toute intégration qui lit `price.sku.product` — ou
  qui déréférence `price.sku` tout court — doit se prémunir contre `null`, sans quoi elle
  casse dès qu'un prix est rattaché à un produit. Lisez le produit dans `price.product` ou
  `price.productId`.
</Warning>

## Opérations courantes

### Créer un prix

```bash
curl -X POST https://api.yabetoo.com/v1/prices \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "productId": "prod_abc123",
    "amount": 9000,
    "currency": "XAF",
    "type": "recurring",
    "billingInterval": "month",
    "billingIntervalCount": 1
  }'
```

### Récupérer un prix

```bash
curl https://api.yabetoo.com/v1/prices/price_abc123 \
  -H "Authorization: Bearer sk_live_..."
```

### Lister les prix d'un produit

```bash
curl "https://api.yabetoo.com/v1/prices?productId=prod_abc123" \
  -H "Authorization: Bearer sk_live_..."
```

`GET /v1/prices` accepte les filtres suivants, combinables entre eux :

| Filtre | Description |
|--------|-------------|
| `productId` | Uniquement les prix de ce produit |
| `skuId` | Uniquement les prix de ce SKU. Déprécié, comme le champ lui-même |
| `type` | `one_time` ou `recurring` |
| `active` | `true` ou `false` |

### Désactiver un prix

<Note>
  Les prix ne peuvent pas être supprimés s'ils sont associés à des abonnements actifs. Utilisez la désactivation à la place.
</Note>

```bash
curl -X PUT https://api.yabetoo.com/v1/prices/price_abc123 \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "active": false
  }'
```

## Stratégies de tarification

### Offre mensuelle vs annuelle

Proposez une réduction pour l'abonnement annuel :

```json
{
  "prices": [
    {
      "productId": "prod_saas_pro_mensuel",
      "amount": 9000,
      "currency": "XAF",
      "type": "recurring",
      "billingInterval": "month",
      "billingIntervalCount": 1
    },
    {
      "productId": "prod_saas_pro_annuel",
      "amount": 90000,
      "currency": "XAF",
      "type": "recurring",
      "billingInterval": "year",
      "billingIntervalCount": 1
    }
  ]
}
```

<Tip>
  9 000 XAF/mois vs 90 000 XAF/an représente environ 2 mois gratuits, ce qui incite les clients à s'engager sur l'année.
</Tip>

<Note>
  Les deux prix appartiennent à deux produits distincts. Au sein d'une même portée — le même
  SKU, ou le niveau produit — un second prix récurrent dans la même devise désactive le
  premier : mensuel et annuel demandent donc soit deux SKU, soit deux produits.
</Note>

### Tarification par paliers

Créez un produit par niveau de service, chacun avec son prix :

```
Produit "App Cloud — Starter"     → Price 5 000 XAF/mois
Produit "App Cloud — Pro"         → Price 15 000 XAF/mois
Produit "App Cloud — Enterprise"  → Price 50 000 XAF/mois
```

## Getters utiles

Le modèle Price fournit des getters pour faciliter les vérifications :

```typescript
// Vérifier le type de prix
price.isRecurring  // true si type === 'recurring'
price.isOneTime    // true si type === 'one_time'
```

## Bonnes pratiques

<AccordionGroup>
  <Accordion title="Format des montants">
    Les montants sont exprimés dans l'unité principale de la devise, jamais en centimes :
    - XAF : 25000 = 25 000 XAF
    - XOF : 25000 = 25 000 XOF
    - EUR : 39 = 39 €

    Les décimales sont acceptées et le montant ne peut pas dépasser `99999999.99`. L'API le renvoie sous forme de chaîne décimale (`"25000.00"`).
  </Accordion>

  <Accordion title="Rattachement d'un prix">
    - Envoyez toujours `productId` : c'est le lien canonique
    - `skuId` ne subsiste que pour les intégrations existantes, et il est déprécié
    - Lisez le produit dans `price.product`, jamais dans `price.sku.product`
  </Accordion>

  <Accordion title="Prix actifs/inactifs">
    - Désactivez les anciens prix plutôt que de les supprimer
    - Gardez les prix actifs au minimum nécessaire
    - Gardez en tête qu'un nouveau prix désactive le prix actif de même produit, devise, type et portée (même SKU, ou niveau produit)
  </Accordion>

  <Accordion title="Périodes d'essai">
    - 7 à 14 jours est généralement optimal
    - Trop court : pas assez de temps pour évaluer
    - Trop long : perte de revenus potentielle
  </Accordion>

  <Accordion title="Multi-devises">
    - Ajustez les prix pour chaque marché (pas de simple conversion)
    - Tenez compte du pouvoir d'achat local
    - Utilisez des prix psychologiques (9 000 XAF plutôt que 8 750 XAF)
  </Accordion>
</AccordionGroup>
