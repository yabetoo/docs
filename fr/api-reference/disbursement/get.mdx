## Endpoint

```bash
GET https://pay.sandbox.yabetoopay.com/v1/disbursement/{id}   # Sandbox
GET https://pay.api.yabetoopay.com/v1/disbursement/{id}       # Production
```

## Authentification

Utilisez votre clé secrète dans l'en-tête `Authorization` :

```bash
Authorization: Bearer YOUR_SECRET_KEY
```

## Paramètres de chemin

| Paramètre | Type | Description |
|-----------|------|-------------|
| `id` | `string` | L'ID du décaissement |

### Statuts du décaissement

| Statut | Description |
|--------|-------------|
| `processing` | En cours de traitement |
| `succeeded` | Décaissement réussi |
| `failed` | Décaissement échoué |
| `canceled` | Décaissement annulé |

### Champ `review`

`review` vaut `null` pour un décaissement qui n'a pas été retenu pour vérification (cas général). Lorsqu'il l'a été, `review` indique où en est cette vérification pendant que le `status` reste `processing` :

```json
{
  "id": "wt_RMqehxy8NNi1ocJFG2SSAZMj81m6spo72vnZ",
  "status": "processing",
  "review": {
    "status": "open",
    "opened_at": "2025-03-17T09:24:57.559Z",
    "closed_at": null
  }
}
```

| `review.status` | Signification |
|-----------------|---------------|
| `open` | Vérification en cours, rien n'a été envoyé à l'opérateur |
| `approved` | Vérification validée, le décaissement suit le cycle habituel |
| `rejected` | Vérification refusée : `status: "failed"`, `failureCode: "risk_review_rejected"` ou `"risk_blocked"` (refusé après coup) ; les fonds sont rendus |
| `expired` | Aucune décision sous 48 h : `status: "failed"`, `failureCode: "risk_review_expired"` |

`closed_at` est renseigné dès que la revue n'est plus `open`. Voir [Créer un décaissement](/fr/api-reference/disbursement/create).
